# `cua` —— 桌面控制

**服务名**：`cua`　**工具数**：9　**可写，每次操作需你明确同意**

> 这个 MCP 不是这次配的，是之前就有的（`cordis.patch.yml` 里的 `mcp-cua`），
> 指向 `C:\Users\<user>\Desktop\windows_local_ai_agent`。

用来操作图形界面：截屏、点击、输入、按键。适合处理**没有命令行接口**的东西。

---

## 强制确认机制

`click` / `type_text` / `press` / `hotkey` / `scroll` 这几个工具**在调用前必须得到你的明确同意**。

这不是我的自觉，是工具层面的硬约束：我在对话里说明要点哪里、输入什么，你说同意，才执行。

`screenshot` / `screen_size` / `move` / `wait` 不需要确认（只读或不产生副作用）。

---

## 工具清单

| 工具 | 作用 | 需确认 |
|---|---|---|
| `screenshot` | 截取整个桌面 | 否 |
| `screen_size` | 查真实分辨率 | 否 |
| `move` | 移动鼠标（不点击） | 否 |
| `wait` | 等待，最多 30 秒 | 否 |
| `click` | 在坐标点击 | **是** |
| `type_text` | 输入文字（支持中文） | **是** |
| `press` | 按单个键（enter/esc/tab/f5…） | **是** |
| `hotkey` | 组合键（`["ctrl","s"]`） | **是** |
| `scroll` | 滚轮滚动 | **是** |

---

## 坐标怎么来

**所有坐标都用截图上的像素坐标**，不是你的真实屏幕坐标。

`screenshot` 会把图缩放到最长边 1600 像素再返回，你在这张图上看到的 (x, y)
直接传给我即可，服务端负责换算回真实分辨率。

```
真实分辨率 2560×1600  →  截图 1600×1000  →  你按 1600×1000 报坐标
```

## 典型用法

| 场景 | 怎么问 |
|---|---|
| 看屏幕现在什么样 | 「截个图看看」 |
| 点某个按钮 | 「点一下右下角那个确定」 |
| 填表单 | 「在搜索框输入 xxx 然后回车」 |
| 快捷键 | 「按 Ctrl+S 保存」 |
| 滚动页面 | 「往下滚一点」 |

---

## 注意

| 坑 | 说明 |
|---|---|
| 我看的是截图不是 DOM | 可能定位不准，复杂界面建议先截图确认 |
| 窗口可能被遮挡 | 操作前最好把目标窗口置顶 |
| 输入中文走剪贴板 | `type_text` 用剪贴板粘贴实现，会覆盖你当前的剪贴板内容 |
| 分辨率变化 | 换显示器或改缩放后，先调 `screen_size` 重新确认 |
| 权限 | 需要桌面会话，锁屏或远程会话里可能失败 |

---

## 和其他 MCP 的关系

| 想做的事 | 优先用 |
|---|---|
| 文件操作、命令执行 | `shell`（更准、可审计） |
| 读文档内容 | `docs` |
| 看代码历史 | `git` |
| **只有 GUI 才能做的** | `cua`（兜底） |

`cua` 是最后手段。能用命令解决的，不要用点击——因为点击依赖截图判断，
一旦界面变化就可能点错位置。
